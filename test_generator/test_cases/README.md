# Vim compatibility regression cases

Cases 75–111 cover the missing commands and behavior differences identified in
the VimLineEdit review. They intentionally describe Vim behavior, so they are
expected to fail until the corresponding implementation changes are made.

Each case has the existing `.keystrokes.txt` / `.txt` pair. It starts in an empty
normal-mode buffer, inserts its initial text, returns to the start with `gg0`,
runs the sequence below, and ends with `:wq<CR>`. Cursor-only behavior is made
observable by a final `x` deletion. Indentation tests use an interior line so
that the runner's outer whitespace trimming cannot hide the difference.

Expected output was generated by replaying each complete keystroke file in real
Vim with no user configuration or viminfo. Use `feedkeys()` with the `t` flag
to preserve typed-key undo boundaries; plain `-s` replay groups insertions and
would give incorrect expectations for the undo tests:

```sh
vim -Nu NONE -N -n -i NONE -X \
  -c 'call feedkeys(join(readfile("/absolute/path/test_case_75.keystrokes.txt", "b"), "\n"), "xt")' \
  /tmp/new-empty-output.txt
```

The output path must not already exist. Its saved bytes become the corresponding
expected `.txt` file. Indentation cases use Vim defaults (`shiftwidth=8`,
`tabstop=8`, `noexpandtab`, and no filetype indent plugin).

The test runner recognizes `<C-r>` as byte `0x12`, using the same platform
modifier convention as the other existing control-key tests.

## Additional compatibility regressions (118–160)

These 43 cases reproduce the follow-up review findings. Their expected output
was generated from the complete keystroke files using a clean Vim instance
(`-Nu NONE -N -n -i NONE -X --not-a-term`) and the `feedkeys(..., "xt")`
method above. Do not use Ex mode (`-e` / `-es`) for this replay: Escape in a
search command line behaves differently there, affecting case 119.

Every case starts in an empty normal-mode buffer, inserts its initial text,
returns to `gg0`, and executes the sequence in the table. An additional
`<Esc>:wq<CR>` terminates each fixture, cancelling any pending command before
saving. Cases involving significant line boundaries or surrounding whitespace
use interior lines where necessary so the runner's `.trimmed()` comparison
cannot hide the regression. These are intentionally failing tests; no editor
implementation changes accompany them.

**Unicode runner limitation:** Cases 137–138 contain UTF-8 keystrokes and have
Vim-generated UTF-8 expectations. The current runner iterates bytes rather
than decoding Unicode characters, so their failures also expose the runner's
input-decoding limitation. They cannot isolate the editor's `toLatin1()` symbol
conversion bug until Unicode key replay is supported. Neither the runner nor
the editor is changed here.
